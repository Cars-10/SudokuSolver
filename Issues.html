Critical Issues

These languages have fundamental issues preventing execution.

AppleScript Critical

Issue: AppleScript is macOS-only and requires the osascript interpreter which is not available on Linux.

Toolchain: osascript (macOS built-in)

Docker Status: Cannot run in Docker (Linux-based container)

Workaround

Run AppleScript benchmarks directly on macOS host machine outside of Docker.

Red Critical

Issue: Red language has very limited platform support. The Linux binary is x86_64 only and may have runtime issues.

Toolchain: red

Known Problems:

  • No ARM64/aarch64 support
  • GTK dependencies may be missing
  • Binary compatibility issues across Linux distributions
  • Intermittent download failures from official source
Workaround

Try running on native x86_64 Linux host, or skip this benchmark if issues persist.

Platform-Specific Issues

These languages have architecture or platform dependencies.

Assembly Warning

Issue: Assembly code is architecture-specific. The implementation has separate files for x86_64 and ARM64.

Toolchains:

  • x86_64: nasm (Netwide Assembler)
  • ARM64: gcc (GAS assembler)

Files:

  • Sudoku.asm - x86_64 NASM syntax
  • Sudoku_arm64.s - ARM64 GAS syntax
Automatic Detection

The runMe.sh script automatically detects architecture via uname -m and uses the appropriate source file.

BASIC (FreeBASIC) Warning

Issue: FreeBASIC has complex cross-compilation requirements on Apple Silicon Macs. Requires Intel toolchain and Rosetta 2.

Toolchain: fbc (FreeBASIC Compiler)

macOS ARM64 Issues:

  • Requires arch -x86_64 prefix for compilation
  • Needs Intel versions of GCC libraries
  • SDK path must be explicitly specified
Docker Solution

Use Docker (x86_64 container) which has native FreeBASIC support without cross-compilation complexity.

Swift Warning

Issue: Swift installation varies significantly between macOS (Xcode) and Linux (standalone toolchain).

Toolchain: swiftc

Linux Notes:

  • Requires downloading Swift toolchain from swift.org
  • Large download size (~500MB compressed)
  • May have library path issues
Docker Solution

Dockerfile includes Swift 6.0 toolchain pre-installed and configured.

Objective-C Warning

Issue: Objective-C runtime support varies between platforms. macOS has full support via Clang, Linux requires GNUstep.

Toolchains:

  • macOS: clang (with Foundation)
  • Linux: gobjc (GCC Objective-C)
Note

The Sudoku solver uses minimal Objective-C features and should compile on both platforms with GCC's gobjc.

Brainfuck Info

Issue: No standard Brainfuck compiler/interpreter. The implementation includes a custom C interpreter.

Toolchain Options:

  • bfc - Optimizing Brainfuck compiler (preferred)
  • bf_interpreter - Custom C interpreter (fallback)
  • beef - Alternative interpreter

Special Note: The Brainfuck solver has Matrix 1 hardcoded and does not read matrix files dynamically.

Docker Solution

Dockerfile includes a simple Brainfuck interpreter compiled from C.

Stub/Incomplete Implementations

These directories exist but have no working implementation.

Expect Stub

Status: Directory contains only Media subdirectory. No solver implementation or runMe.sh.

Expected Toolchain: expect (Tcl extension)

Reason: Expect is designed for automating interactive programs, not computational tasks. Implementation may not be practical.

F# (original directory) Stub

Status: The F# directory (with special character) is a stub. The actual implementation is in F_Sharp directory.

Note: Directory names with special characters (#) can cause issues with shell scripts and file systems.

Use F_Sharp Instead

The working F# implementation is located at Algorithms/BruteForce/F_Sharp/

SQL Stub

Status: Directory contains only Media subdirectory. No solver implementation.

Challenge: Pure SQL is not Turing-complete without extensions. Implementing a backtracking algorithm in standard SQL is not feasible.

Alternative: See SQLite directory for a JavaScript wrapper that uses SQLite for storage.
